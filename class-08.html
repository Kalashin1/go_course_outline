Files, JSON persistence and a well-structured CLI

Give your CLI durable storage and a maintainable design. Read and write JSON files, organize commands and handle filesystem errors.

⏱ 2 hoursExplain · Demonstrate · PracticeChallenge included

Learning objectives

By the end of this class, you should be able to

  • ✓Read and write files using Go's standard library.
  • ✓Encode and decode JSON data safely.
  • ✓Persist CLI data between program runs.
  • ✓Separate command parsing, application logic and storage responsibilities.
  • ✓Understand when a third-party CLI framework may be useful.

Lesson content

Concepts we will cover

File operations

os.ReadFile, os.WriteFile, file permissions, paths and handling missing files.

JSON persistence

json.Marshal/Unmarshal and Encoder/Decoder; struct tags; malformed or empty file behavior.

Storage design

Define a storage interface or focused functions; keep file operations out of command parsing.

Command expansion

Add update/complete/delete commands; validate IDs; provide useful success/failure messages.

Framework awareness

When tools such as Cobra are useful; understand the standard library version first.

Code walkthroughs

Learn by reading and running Go code

Type these examples into your own project rather than only copying them. Run each one, change a value, predict the output, and run it again. Some examples are focused fragments; the notes explain any imports or surrounding code they need.

Save and load JSON

Example 1
package main

import (
	"encoding/json"
	"os"
)

type Task struct {
	Title string `json:"title"`
	Done  bool   `json:"done"`
}

func saveTasks(path string, tasks []Task) error {
	data, err := json.MarshalIndent(tasks, "", "  ")
	if err != nil { return err }
	return os.WriteFile(path, data, 0644)
}

func loadTasks(path string) ([]Task, error) {
	data, err := os.ReadFile(path)
	if err != nil { return nil, err }
	var tasks []Task
	err = json.Unmarshal(data, &tasks)
	return tasks, err
}
Teaching note: MarshalIndent converts Go values to readable JSON; Unmarshal parses JSON into a Go value. File operations return errors that callers must handle.

Use the persistence functions

Example 2
tasks := []Task{
	{Title: "Learn Go structs", Done: true},
	{Title: "Build a CLI app", Done: false},
}

if err := saveTasks("tasks.json", tasks); err != nil {
	log.Fatal(err)
}
loaded, err := loadTasks("tasks.json")
if err != nil { log.Fatal(err) }
fmt.Printf("Loaded %d tasks\n", len(loaded))
Teaching note: This usage fragment goes inside main and needs the log and fmt imports. Discuss relative file paths, permissions and what should happen when tasks.json does not exist yet.

Practice while you learn

After each example, make one deliberate change and explain what changed. If the compiler reports an error, read the file name and line number, fix one issue at a time, then run the example again.

End-of-class challenge

Your turn to prove your understanding

Turn the CLI into a **persistent task tracker**. It must support `add`, `list`, `complete` and `delete`, store tasks in a JSON file, and preserve data between separate program runs. Handle a missing data file gracefully and report malformed JSON clearly.

Submission checklist

  • □All four commands work from the terminal.
  • □Tasks remain available after the program exits and restarts.
  • □JSON is encoded/decoded using the standard library.
  • □Missing file, malformed file and unknown task ID cases are handled cleanly.
  • □Command parsing, task logic and file persistence are separated into sensible functions or packages.

Optional stretch goal

Allow the user to choose a data-file path with a --file flag and add a --json output option.
