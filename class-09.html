Learning objectives

By the end of this class, you should be able to

  • ✓Write unit and table-driven tests for CLI and application logic.
  • ✓Use go test, go vet and gofmt as part of a quality workflow.
  • ✓Build an executable for the current platform and understand cross-compilation basics.
  • ✓Write useful project documentation and configuration instructions.
  • ✓Demonstrate the REST API and CLI and explain their architecture.

Code walkthroughs

Learn by reading and running Go code

Type these examples into your own project rather than only copying them. Run each one, change a value, predict the output, and run it again. Some examples are focused fragments; the notes explain any imports or surrounding code they need.

Write a table-driven unit test

Example 1
package main

import "testing"

func add(a, b int) int { return a + b }

func TestAdd(t *testing.T) {
	tests := []struct {
		name string
		a, b int
		want int
	}{
		{"positive", 2, 3, 5},
		{"negative", -2, -3, -5},
		{"zero", 0, 4, 4},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			if got := add(tt.a, tt.b); got != tt.want {
				t.Errorf("add() = %d, want %d", got, tt.want)
			}
		})
	}
}
Teaching note: Table-driven tests keep related cases together. Run go test ./... and use go test -cover ./... to inspect statement coverage.

Format, vet and build

Example 2
gofmt -w .
go vet ./...
go test ./...
go build -o bin/course-app .

# Run the compiled application
./bin/course-app
Teaching note: Explain each step: format source, run static checks, execute tests, then compile a binary. On Windows, run bin\course-app.exe instead of the final command.

Practice while you learn

After each example, make one deliberate change and explain what changed. If the compiler reports an error, read the file name and line number, fix one issue at a time, then run the example again.

Guided practice

Let's build something together

End-of-class challenge

Your turn to prove your understanding

Submit and present your **Go mini-portfolio**: (1) a MongoDB-backed Task REST API and (2) a persistent task-tracker CLI. Both projects must build, have a README and include automated tests for important behavior. Demonstrate a normal workflow and at least one handled error in each project.

Submission checklist

  • □Both projects compile successfully and have clear run instructions.
  • □API demonstrates CRUD operations backed by MongoDB and handles invalid/missing data.
  • □CLI supports add/list/complete/delete with persistent JSON storage.
  • □Each project includes meaningful tests and passes go test ./....
  • □Learner can explain packages, structs, interfaces, errors and how each app handles input and failures.

Optional stretch goal

Add a GitHub Actions workflow to run gofmt checks, go test ./... and go vet ./... on each push.
