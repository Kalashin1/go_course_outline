Learning objectives

By the end of this class, you should be able to

  • ✓Organize handlers, models and data access into understandable layers.
  • ✓Validate incoming data and return consistent error responses.
  • ✓Use request context and timeouts for database operations.
  • ✓Test handlers and core logic with Go's testing tools.
  • ✓Explain basic API hardening and what remains for production.

Lesson content

Concepts we will cover

Project structure

Separate transport/handlers, domain models, repository/data access and configuration without overengineering.

Validation and responses

Required fields, length limits, allowed values, consistent JSON error format and appropriate 400/404/500 statuses.

Context and timeouts

r.Context, context.WithTimeout, cancellation and passing context into MongoDB operations.

Testing

testing package, httptest, table-driven tests, testing handlers and mocking/stubbing boundaries where practical.

Operational basics

Structured logs, graceful shutdown concept, environment config, CORS/authentication as next steps rather than rushed additions.

Code walkthroughs

Learn by reading and running Go code

Type these examples into your own project rather than only copying them. Run each one, change a value, predict the output, and run it again. Some examples are focused fragments; the notes explain any imports or surrounding code they need.

Validate input before saving

Example 1
package main

import (
	"errors"
	"strings"
)

type CreateUserInput struct {
	Name  string `json:"name"`
	Email string `json:"email"`
}

func (in CreateUserInput) Validate() error {
	if strings.TrimSpace(in.Name) == "" {
		return errors.New("name is required")
	}
	if !strings.Contains(in.Email, "@") {
		return errors.New("a valid email is required")
	}
	return nil
}
Teaching note: Validation protects the application from incomplete input. This simple email check is for teaching only; production systems need stronger validation.

Test an HTTP handler

Example 2
package main

import (
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestHealthHandler(t *testing.T) {
	req := httptest.NewRequest(http.MethodGet, "/health", nil)
	recorder := httptest.NewRecorder()

	healthHandler(recorder, req)

	if recorder.Code != http.StatusOK {
		t.Fatalf("got status %d, want %d", recorder.Code, http.StatusOK)
	}
}
Teaching note: Put tests in files ending with _test.go and run go test ./.... httptest lets you test handlers without starting a real network server. Replace healthHandler with the handler built in class.

Practice while you learn

After each example, make one deliberate change and explain what changed. If the compiler reports an error, read the file name and line number, fix one issue at a time, then run the example again.

End-of-class challenge

Your turn to prove your understanding

Complete and demonstrate a **tested Task REST API**. Include all CRUD routes, input validation, consistent error responses, request-scoped database contexts and automated tests for at least two handlers plus one validation function. Provide a README with setup and run instructions.

Submission checklist

  • □All CRUD routes work against MongoDB.
  • □Invalid input returns 400; missing resources return 404; unexpected failures do not expose secrets.
  • □Database calls receive a request context or timeout.
  • □At least three meaningful automated tests pass with go test ./....
  • □README documents environment variables, database setup and how to run tests.

Optional stretch goal

Implement graceful HTTP server shutdown on an interrupt signal. Add authentication only if the core requirements are already stable.
