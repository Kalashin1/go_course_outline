CLI foundations: commands, flags and terminal interaction

Learn how command-line programs receive input, present output and return useful exit codes. Build a first interactive Go CLI.

⏱ 2 hoursExplain · Demonstrate · PracticeChallenge included

Learning objectives

By the end of this class, you should be able to

  • ✓Explain the difference between command-line arguments, flags and interactive input.
  • ✓Read arguments and flags using the standard library.
  • ✓Print helpful usage and error messages.
  • ✓Choose appropriate exit codes and separate CLI input/output from core logic.
  • ✓Design a simple command interface.

Lesson content

Concepts we will cover

CLI anatomy

Process arguments, os.Args, flags, stdin, stdout, stderr and exit status.

Flags

flag package, typed flags, defaults, descriptions and parsing.

User interaction

Command design

Commands and subcommands; naming; predictable output; keeping business logic outside main.

Code walkthroughs

Learn by reading and running Go code

Type these examples into your own project rather than only copying them. Run each one, change a value, predict the output, and run it again. Some examples are focused fragments; the notes explain any imports or surrounding code they need.

Read command-line flags

Example 1
package main

import (
	"flag"
	"fmt"
)

func main() {
	name := flag.String("name", "Guest", "name to greet")
	verbose := flag.Bool("verbose", false, "show extra detail")
	flag.Parse()

	fmt.Printf("Hello, %s!\n", *name)
	if *verbose { fmt.Println("Verbose mode is enabled") }
}
Teaching note: The flag package parses options such as -name=Ada and -verbose. String and bool return pointers, so dereference them with * after flag.Parse().

Run it from the terminal

Example 2
go run . -name=Ada -verbose

go run . -help
Teaching note: Demonstrate defaults, custom values and built-in help. Ask learners to predict output before running each command.

Practice while you learn

After each example, make one deliberate change and explain what changed. If the compiler reports an error, read the file name and line number, fix one issue at a time, then run the example again.

End-of-class challenge

Your turn to prove your understanding

Build a **task command-line interface** with at least `add` and `list` commands. `add` should accept a task title, `list` should display tasks, and invalid commands or missing values should show helpful usage instructions. Use standard-library tools before reaching for a CLI framework.

Submission checklist

  • □Supports at least two commands or clearly parsed command actions.
  • □Accepts at least one flag or argument.
  • □Shows helpful usage for invalid input.
  • □Uses stdout for normal output and stderr for errors where appropriate.
  • □Core task logic is not all written directly inside main.

Optional stretch goal

Add `done` and `delete` commands and support a `--help` message.
