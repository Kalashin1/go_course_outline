HTTP fundamentals and your first Go REST endpoint

Move from Node.js route handlers to Go's net/http package. Understand HTTP requests and responses, build handlers and return JSON.

⏱ 2 hoursExplain · Demonstrate · PracticeChallenge included

Learning objectives

By the end of this class, you should be able to

  • ✓Explain the request-response lifecycle and common HTTP methods/status codes.
  • ✓Create an HTTP server using net/http.
  • ✓Write handlers that read request data and produce responses.
  • ✓Encode and decode JSON using encoding/json.
  • ✓Design resource-oriented REST endpoints.

Code walkthroughs

Learn by reading and running Go code

Type these examples into your own project rather than only copying them. Run each one, change a value, predict the output, and run it again. Some examples are focused fragments; the notes explain any imports or surrounding code they need.

Create a small JSON REST endpoint

Example 1
package main

import (
	"encoding/json"
	"log"
	"net/http"
)

type Message struct {
	Text string `json:"text"`
}

func hello(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusOK)
	_ = json.NewEncoder(w).Encode(Message{Text: "Hello from Go"})
}

func main() {
	http.HandleFunc("GET /hello", hello)
	log.Println("Listening on :8080")
	log.Fatal(http.ListenAndServe(":8080", nil))
}
Teaching note: The standard net/http package routes requests to handlers. A handler receives a ResponseWriter and Request; JSON encoding writes a valid JSON response.

Try the endpoint

Example 2
curl -i http://localhost:8080/hello

# Expected response body:
# {"text":"Hello from Go"}
Teaching note: Run the server with go run . in one terminal, then send the HTTP request from another. Inspect the status code and Content-Type header as well as the body.

Practice while you learn

After each example, make one deliberate change and explain what changed. If the compiler reports an error, read the file name and line number, fix one issue at a time, then run the example again.

End-of-class challenge

Your turn to prove your understanding

Build the first version of a **Task REST API** with `GET /health`, `GET /tasks` and `POST /tasks`. Use structs for request/response data, return JSON with the correct content type, and use meaningful HTTP status codes. Data can remain in memory for this class.

Submission checklist

  • □Server starts and listens on a configurable or clearly documented port.
  • □All three endpoints work when tested with curl or an API client.
  • □POST decodes JSON and rejects malformed or empty task titles.
  • □Responses are JSON and use sensible status codes.

Optional stretch goal

Add `GET /tasks/{id}` using the routing patterns available in the installed Go version, or parse the path carefully if using a basic mux.

Before the next class
